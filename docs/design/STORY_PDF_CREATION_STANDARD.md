# Curiofold — Story PDF Creation Standard

**Version:** 1.0  
**Status:** Authoritative PDF composition and production standard  
**Owner:** Curiofold Brand & Editorial Design  
**Audience:** PDF creation agents, Codex / engineering, editorial systems, QA, future designers  
**Scope:** How approved Story material is organised, composed and developed into a Curiofold PDF  
**Related documents:** `docs/design/STORY_PDF_DESIGN.md`, `docs/design/PRODUCT_DESIGN.md`

---

# 0. Purpose

This document defines the **required editorial-composition process, page organisation, visual planning, content-fitting, preflight and quality-control rules for creating a Curiofold Story PDF**.

It answers:

> Given approved Story material and approved source/visual inputs, how should that material become a finished Curiofold edition?

This document does **not** define:

- how research agents investigate a subject;
- which AI system performs research;
- how an automated pipeline is orchestrated;
- which PDF rendering library is used;
- how agents communicate;
- how publishing triggers work.

It assumes the creator receives trustworthy editorial inputs.

The creator's responsibility is to transform them into an exceptional Curiofold edition **without inventing missing facts or visual evidence**.

---

# 1. Creation principle

PDF creation is not:

> “Put all the supplied text into the template.”

PDF creation is:

> **Select, sequence, pace, frame and visually explain the material so the Story becomes easier and more compelling to understand.**

The creator must behave like:

- an editorial designer;
- an art director;
- a publication designer;
- a visual editor.

The final edition should feel authored.

---

# 2. Evidence-bound creation

The PDF creator may reorganise and visually express approved material.

It may **not invent factual content to make a layout work**.

Never invent:

- facts;
- dates;
- quotes;
- names;
- routes;
- locations;
- boundaries;
- statistics;
- causal relationships;
- archive credits;
- image provenance;
- object shapes;
- diagrams presented as factual.

If required information is missing:

1. do not hallucinate;
2. do not create plausible-looking filler;
3. use a neutral composition that does not require the missing fact;
4. or flag the missing requirement outside the customer-facing output.

---

# 3. Required input package

Before PDF composition begins, the creator should have, at minimum:

- Story title;
- Story language/locale;
- category;
- target reading time;
- approved body/content;
- approved section/beat information;
- verified dates/numbers/names used in graphics;
- source list;
- quotations with attribution;
- approved visual candidates or sufficient provenance information;
- known rights/licensing constraints where relevant;
- update/publication metadata.

If the input package does not support a proposed factual visual, the creator must not fabricate it.

---

# 4. Define the editorial spine first

Before laying out pages, identify internally:

## 4.1 Core question

What curiosity is the Story answering?

## 4.2 One-sentence thesis

What should the reader understand by the end?

## 4.3 Narrative arc

What changes from beginning to end?

## 4.4 Key beats

Identify approximately **3–6 major beats**.

Examples:

- setup;
- hidden context;
- turning point;
- mechanism;
- consequence;
- synthesis.

## 4.5 Most visual beat

Which part of the Story is naturally best shown rather than merely told?

These planning labels are internal and must not leak into the customer PDF.

---

# 5. Select a dominant Story Mode

Choose the dominant internal behaviour:

- Narrative;
- Explainer;
- Profile/Object;
- Data/Atlas.

A Story may combine modes, but one dominant mode should guide pacing.

The Story Mode is not customer-facing copy.

---

# 6. Create a visual thesis

Before page layout, decide:

> What visual idea makes this Story feel specific?

Examples:

- a geographic choke point;
- a machine cutaway;
- a before/after transformation;
- a sequence of primary-source documents;
- scale;
- migration;
- collapse;
- acceleration;
- network.

The visual thesis should guide:

- cover;
- accent;
- hero selection;
- bespoke device;
- page rhythm.

Do not default to a generic diagram because the subject lacks an obvious photograph.

---

# 7. Build the visual asset plan before layout

For each major Story beat, determine whether it benefits from:

- documentary photo;
- archival image;
- document;
- map;
- diagram;
- data graphic;
- illustration;
- type-only treatment;
- no visual.

A visual plan must answer:

- What does this asset prove/explain?
- Why is it better than text alone?
- Is it authentic or explanatory?
- Is its source known?
- Is its quality sufficient?
- Is it legal/approved to use?
- What caption is required?

Do not start final layout while visual strategy is unresolved.

---

# 8. Authentic-first decision rule

For each proposed synthetic graphic, ask:

> Does a strong authentic visual already exist that would communicate this moment better?

If yes, prefer the authentic visual.

Examples:

- an actual surrender photograph is stronger than three circles on a line;
- an actual archaeological artifact is stronger than a random polygon labelled “ceramic”;
- an actual historical map may be stronger than arbitrary route lines.

Custom graphics are valuable when they explain what authentic imagery cannot.

---

# 9. No-filler decision tree

When a page “needs something visual”:

1. Is there a meaningful authentic asset?
2. Is there verified information suitable for a useful diagram/map/chart?
3. Can typography create the intended pause/emphasis?
4. Can whitespace improve the rhythm?

If all are no:

> **Do not add a filler graphic.**

A page does not need decoration merely because it has empty space.

---

# 10. Create the flatplan before final composition

Before final rendering, define the page sequence.

A normal 6–10 page Curiofold Story may follow:

1. Cover
2. Opening / setup
3. Development
4. Development / visual explanation
5. Turning point / visual beat
6. Development
7. Consequence / synthesis
8. Bespoke device or resolution
9. Conclusion / end matter
10. Sources & Notes

This is an example, not a mandatory ten-page formula.

The Story must determine the count and order.

---

# 11. Every page needs an editorial job

For each planned page, define internally:

- page purpose;
- dominant idea;
- dominant element;
- supporting content;
- target density;
- transition from previous page;
- transition to next page.

If a page has no clear editorial job, combine it with another page or remove it.

---

# 12. Page-role library

Permitted page roles include:

## Cover
Creates desire to read.

## Opening
Begins the Story immediately.

## Reading page
Carries narrative efficiently.

## Documentary page
Lets an authentic visual/document carry meaning.

## Explanation page
Uses a diagram/map/chart to teach.

## Turning-point page
Changes pacing around a major event/idea.

## Comparison page
Shows difference/scale/sequence.

## Resolution page
Synthesises the Story.

## Sources page
Builds trust and traceability.

These roles are internal.

Do not print role names automatically.

---

# 13. Page count discipline

Typical:

**6–10 A4 pages**

Do not target ten pages simply because the system allows ten.

Use fewer when the Story is concise.

Use more only when necessary to preserve:

- readability;
- visual integrity;
- sources;
- narrative structure.

Never pad a Story to look more valuable.

Never compress a Story until readability collapses.

---

# 14. Approximate content-density guidance

These are editorial planning ranges, not hard limits.

## Cover
**0–60 words**

## Opening page
**120–250 words**

## Text-led body page
**220–360 words**

## Mixed text + visual page
**100–240 words**

## Visual-led page
**0–140 words**

## Sources page
As required, while preserving minimum readable type.

Do not reduce type to force compliance.

---

# 15. One dominant element per page

Each normal page should have a clear dominant element.

Examples:

- headline;
- body column;
- photograph;
- timeline;
- map;
- quote;
- number.

Supporting elements must remain subordinate.

Avoid layouts where body, diagram, fact box and giant number all compete equally.

---

# 16. Page transitions

The next page should feel intentional.

Use transitions such as:

- chronological progression;
- zooming from macro to detail;
- question → answer;
- cause → consequence;
- image → explanation;
- dense → sparse;
- archival → contemporary.

Avoid pages that feel like independent cards.

The PDF is a sequence, not a folder of pages.

---

# 17. Pacing plan

Avoid sequences such as:

- text + right-side box;
- text + right-side box;
- text + right-side box;
- text + right-side box.

Instead, vary intelligently:

- text-led;
- visual-led;
- text-led;
- dark/turning beat;
- mixed;
- bespoke device;
- calm resolution.

Variation must come from the Story, not randomness.

---

# 18. The bespoke-device planning step

Select at least one Story-specific visual device.

Before accepting it, answer:

- What factual/editorial idea does it communicate?
- Why is it specific to this Story?
- Could it be replaced by a generic graphic with no loss?
- Is every factual element supported by the supplied material?
- Will the reader understand it quickly?
- Does it look professionally art-directed?

If the answer is weak, redesign it.

Never label the customer-facing section “Memorable Device”.

---

# 19. Visual asset acceptance

A visual may enter final layout only if:

- it has a clear editorial purpose;
- factual status is understood;
- source/provenance is known where required;
- resolution is sufficient;
- crop can work;
- rights/usage state is acceptable;
- caption requirements are known.

Do not use assets simply because they are available.

---

# 20. Documentary visual handling

When documentary imagery exists:

- preserve factual context;
- caption accurately;
- show date/location where useful;
- credit properly;
- do not stylise so aggressively that evidence becomes ambiguous.

Documentary imagery should look like evidence, not generic decoration.

---

# 21. Visual evidence hierarchy

When several visuals are available, prefer the one that maximises:

1. relevance;
2. authenticity;
3. specificity;
4. clarity;
5. emotional/narrative power;
6. visual quality.

A beautiful but irrelevant photo is worse than a modest but highly meaningful document.

---

# 22. Map creation rules

Before creating a map, ensure the input includes verified:

- locations;
- relationships;
- route data where claimed;
- chronology where encoded;
- labels.

A schematic map may simplify geometry.

It may not invent it.

If exact geography is unavailable, do not create a geographic-looking graphic that implies precision.

---

# 23. Diagram creation rules

Before creating a diagram, write one sentence:

> “This diagram will help the reader understand ______.”

If the blank cannot be completed concretely, do not create the diagram.

Every line/arrow/shape should encode something.

Decorative connectors are prohibited.

---

# 24. Chart creation rules

Before charting data:

- identify the comparison;
- identify unit;
- identify time period;
- identify source;
- choose the simplest visual encoding.

Avoid charting when a single sentence or large number is clearer.

---

# 25. Page composition order

For each page:

1. place the dominant content;
2. establish hierarchy;
3. fit body copy at canonical typography;
4. place supporting visual;
5. add caption/source;
6. add running furniture;
7. inspect whitespace;
8. remove unnecessary elements.

Do not start with decoration.

---

# 26. Copy-fit rule

Never fix overflow by immediately:

- shrinking body type;
- tightening line-height;
- shrinking margins;
- shrinking captions below minimum.

Preferred order:

1. edit/restructure content if editorially permitted;
2. move content to another page;
3. change composition;
4. alter image scale;
5. add a page if necessary.

Readability wins.

---

# 27. Widows, orphans and bad breaks

Avoid:

- a heading isolated at the bottom of a page;
- a section heading followed by only one line;
- one orphan line at top of next page;
- splitting a short paragraph unnecessarily;
- separating a figure from its caption;
- separating a quote from attribution;
- breaking a small list across pages without need.

Typography should look intentional.

---

# 28. Paragraph rhythm

Do not manufacture short paragraphs solely to look modern.

Do not create giant text walls.

Paragraph breaks should follow editorial thought.

Single-sentence paragraphs may be used when narratively justified.

---

# 29. Headings

Use section headings to mark meaningful structural change.

Do not insert a heading every few paragraphs.

A short Story should remain a Story, not technical documentation.

---

# 30. Callout selection

A callout is justified when it provides:

- a useful definition;
- a striking number;
- essential context;
- a real quote;
- a compact timeline;
- a necessary source note.

Do not use a callout as a container for information that would read better in the body.

---

# 31. Internal labels and prompts

Before export, search the complete PDF for accidental process language.

Remove labels such as:

- “memorable device”;
- “layout”;
- “placeholder”;
- “image here”;
- “draft”;
- “story mode”;
- “cover family”;
- prompt instructions.

No internal production language should reach the customer.

---

# 32. Caption writing

Every documentary visual caption should be drafted after the visual is chosen.

A caption should:

- identify the subject;
- establish date/location when useful;
- explain relevance;
- avoid speculative language.

Do not copy the body paragraph verbatim.

---

# 33. Credits

Credits must be factual.

Do not guess:

- photographer;
- archive;
- licence;
- year.

If credit information is incomplete, the asset remains unresolved.

---

# 34. Source-page organisation

Sources should be grouped logically, for example:

- by section;
- by theme;
- primary vs secondary;
- or ordered by first use.

Do not dump raw browser URLs without context.

Prefer human-readable source entries.

Links may remain clickable.

---

# 35. End-matter order

Recommended order:

1. concluding/synthesis line if needed;
2. Sources & Notes;
3. editorial/update note;
4. one subtle related-rabbit-hole cue;
5. Curiofold mark.

Do not over-market the reader immediately after completion.

---

# 36. Language versioning

For translated editions:

- reflow/recompose;
- do not preserve English line breaks;
- allow title size within approved ranges;
- adapt captions;
- localise dates/numbers;
- keep names/proper nouns correct.

A translation is not finished until its layout is re-QA'd.

---

# 37. Accessibility must be built before export

Ensure the source composition supports:

- heading structure;
- paragraph structure;
- figure/caption relationships;
- logical reading order;
- alt text;
- language;
- link semantics.

Accessibility should survive export.

---

# 38. Alt text

Informational figures require concise meaningful alt text.

Alt text should communicate the informational purpose, not every decorative detail.

Decorative elements should be marked as artifacts where appropriate.

---

# 39. PDF metadata

Final PDF metadata should include:

- title;
- language;
- Curiofold as appropriate;
- subject/description when available;
- creation/update metadata where appropriate.

Do not ship default tool filenames/titles as visible metadata.

---

# 40. Preflight — typography

Before release, verify:

- Newsreader/Instrument Sans render correctly;
- intended fonts are embedded/subset as appropriate;
- no fallback font accidentally replaced a style;
- no missing glyphs;
- no overset/clipped text;
- accents/diacritics render correctly.

---

# 41. Preflight — images

Verify:

- no missing linked asset;
- no outdated asset version;
- no stretched aspect ratio;
- no unintended crop;
- sufficient effective resolution;
- no visible compression damage;
- no accidental colour shift that changes meaning;
- all required credits/captions exist.

For print-capable imagery, **300 ppi is preferred** at final size.

Historically important lower-resolution assets may be used deliberately at an appropriate size.

---

# 42. Preflight — layout

Verify:

- correct A4 dimensions;
- intended page count;
- no accidental blank pages;
- no clipping;
- no unexpected page overlap;
- folios correct;
- running heads correct;
- cover has no folio;
- consistent margins;
- no random alignment drift.

---

# 43. Preflight — accessibility

Verify:

- PDF is tagged;
- logical reading order;
- primary language set;
- meaningful figures tagged;
- decorative items treated appropriately;
- alt text present where required;
- links meaningful;
- text extractable/selectable;
- no security setting blocks assistive access.

---

# 44. Preflight — visual truth

Verify:

- documentary assets are authentic;
- synthetic/editorial visuals are not disguised as evidence;
- maps do not imply unsupported precision;
- charts use supplied data only;
- diagram labels are verified;
- credits are real;
- dates are correct.

A visually beautiful falsehood is a failed Curiofold page.

---

# 45. Preflight — customer-facing language

Verify that the PDF contains no:

- internal instruction;
- placeholder;
- template name;
- prompt language;
- process note;
- raw agent reasoning;
- system terminology.

The user sees only finished editorial language.

---

# 46. Thumbnail-sequence review

View all pages simultaneously as thumbnails.

Check:

- rhythm;
- repetition;
- brand coherence;
- density curve;
- image repetition;
- visual peaks;
- quiet moments.

If pages look mechanically identical, redesign.

If pages look unrelated, restore system discipline.

---

# 47. Actual-size review

Review at normal reading scale.

Check:

- body comfort;
- caption comfort;
- source comfort;
- colour contrast;
- visual sharpness;
- page balance.

Do not judge only while zoomed in.

---

# 48. High-zoom review

Inspect important visuals at higher zoom.

Check:

- vector crispness;
- raster artifacts;
- low-resolution upscaling;
- hairline quality;
- label clarity;
- clipping.

---

# 49. Screen-context review

Preview the PDF in the intended in-platform viewer context.

Verify that:

- the cover reads at fit-width;
- body remains readable after reasonable zoom;
- margins do not make content unnecessarily tiny;
- page edges are clear;
- small labels remain useful.

---

# 50. Print sanity review

Even though digital is primary, A4 PDFs should remain credible when printed.

Check:

- contrast;
- text size;
- image quality;
- colour relationships.

---

# 51. AI-smell review

Ask:

- Are there generic blobs?
- Are there circles/arrows with no real information?
- Does the same visual grammar repeat too much?
- Are there visuals that look plausible but are unsupported?
- Are there fake maps?
- Is there an image that exists only because “the page needed an image”?
- Does any label sound like a prompt instruction?
- Does the Story lack authentic imagery despite the subject offering it?

If yes, revise before release.

---

# 52. Paid-value review

Ask:

> If I had just paid for this Story, would opening it increase or decrease my trust in Curiofold?

The correct answer must be:

> **Increase.**

Then ask:

- Is there visible craft?
- Is the content comfortably readable?
- Is at least one visual memorable?
- Is the cover desirable?
- Does the edition feel specific rather than generic?
- Does the PDF feel more finished than a normal web article?

If not, the PDF is not ready.

---

# 53. Hard rejection conditions

Reject the PDF immediately if it contains:

- fabricated documentary visual;
- fabricated credit;
- fake data;
- unsupported map;
- random placeholder shapes passed off as evidence;
- internal design-system language;
- clipped/overset text;
- missing fonts;
- unreadable sources;
- obvious low-resolution hero imagery;
- generic filler graphics that materially cheapen the edition.

---

# 54. Revision priority

When a PDF fails, fix in this order:

1. factual/visual truth;
2. weak visual strategy;
3. cover;
4. hierarchy;
5. pacing;
6. typography/readability;
7. image quality/crops;
8. captions/credits;
9. micro-alignment/polish.

Do not polish a weak concept before fixing the concept.

---

# 55. Do not preserve weak generated precedent

A previously generated PDF is **not** automatically a design reference.

Only use prior Stories as precedent when they have been explicitly accepted as Curiofold-quality examples.

Rejected or experimental PDFs must not teach future editions weak habits.

---

# 56. Approved-reference principle

As Curiofold builds a library of approved Stories, future PDF creation should compare against the best accepted examples for:

- cover strength;
- pacing;
- diagram quality;
- visual sourcing;
- source treatment;
- typography;
- perceived value.

The quality ceiling should rise over time.

---

# 57. Creation-complete definition

A Story PDF is complete only when:

- content is fitted without compromising readability;
- page sequence has intentional rhythm;
- every visual has a job;
- authentic visuals were preferred where stronger;
- bespoke device is meaningful;
- no internal instructions leaked;
- sources and visual credits are complete;
- accessibility structure is present;
- preflight has no critical errors;
- design score meets `STORY_PDF_DESIGN.md`;
- the paid-value test passes.

---

# 58. Governing principle

> **Do not decorate information. Art-direct understanding.**

The PDF creator's job is not to prove that every available design component was used.

The job is to make the Story:

- clearer;
- more desirable;
- more memorable;
- more trustworthy;
- more valuable.

When in doubt:

> **Choose the simpler, truer, better-composed solution.**
